Option C — from signal to order

Every step from the Streamlit / cloud engine that decides the weights to the laptop executor that places the orders on IBKR paper. The heavy model runs in the cloud; the money-moving steps run only on the laptop.

Cloud (Streamlit / GitHub Action) Laptop (next to IB Gateway) Guard — aborts if it fails Order sizing
Cloud

Decide the weights & publish the signed book

Python 3.12 · full model stack
1

Run every strategy

Fetch Yahoo data and run each app's signal (BTC via the CT engine, Gold via its divergence engine, the ETFs via the shared daily engine). Yields per-instrument signals, positions and backtests.

overall_core.run_universe()
2

Optimise the blend

Search long-only weights (max Sharpe / return) under per-kind caps for the chosen risk profile, then apply the forward fundamental tilt.

overall_core.optimize_weights()
3

Overlay live prices

Pull the current spot quote for each instrument and lay it over the last-bar close.

overall_core.fetch_spot() → apply_spot()
4

Drop trend-broken names

Flag any position whose live price has fallen through its trend filter — it would exit next bar — so it isn't funded today. include_entries=True covers fresh entries too.

overall_core.live_exit_keys()
5

Gate the allocation → target weights

Deploy capital only to instruments the signal is long, size each slice by the optimal weight tilted by entry priority, water-fill to the caps; the undeployed remainder is cash. This produces the target % per instrument.

overall_core.signal_gated_allocation(force_exit=…)
6

Assemble the book

Package weights + execution prices (BTC → IBIT), the as-of signal bar and a generation timestamp into the v1 schema.

target_book.build_payload() compute_target_book() wraps steps 1–6
7

Sign & write

HMAC-SHA256 sign with OVERALL_BOOK_SECRET, then write the artifact. The GitHub Action runs this and commits it to the branch.

target_book.sign() → data/overall/target_book.json scripts/publish_target_book.py
The Streamlit app (overall_app.py target_book_app.py) runs the same steps 1–5 to display the allocation, the Target Book viewer, and the include/exclude control — and can download an adjusted, re-signed book. It never connects to IBKR. The automated publisher is the GitHub Action running publish_target_book.py.
▼
git commit → branch → git pull (or raw URL) the signed target_book.json is the only thing that crosses the boundary

Laptop

Verify, size the orders & execute

ib_async only · no model
8

Pull the latest book

Task Scheduler fires the wrapper, which fast-forwards the branch to grab the freshest committed book, then runs the executor.

scripts/ibkr_execute_daily.ps1 → git pull
9

Load the book

Read the target book from --file, --url, or stdin.

scripts/ibkr_execute_book.py
10

Verify signature Guard

Recompute the HMAC with the shared secret. A tampered or forged book aborts here — no orders.

target_book.verify_signature()
11

Validate freshness & market day Guard

Reject a stale signal bar or a book generated too long ago; skip weekends and US holidays.

target_book.validate() ibkr_common.is_trading_day()
12

Connect to IB Gateway Guard

Open the socket to the paper gateway and confirm the account is a paper (DU…) account — else abort.

ibkr_common.Broker() → 127.0.0.1:4002
13

Read the account

Fetch net-liquidation value and current positions (IBKR symbols mapped back to signal keys — IBIT → BTC).

Broker.net_liq() Broker.positions_by_key()
14

Decide buys / sells & size them Sizing

target_shares = weight × net_liq ÷ price. Diff vs held → delta > 0 buy, delta < 0 sell; a held name at 0% is fully closed. Skip anything inside the no-trade band (1% of NAV). Order sells first.

ibkr_common.build_order_plan()
15

Place the orders

Transmit market orders — sells leg first (await fills to free buying power), then the buys leg.

ibkr_common.Broker.place() → MarketOrder
16

Fills land in the paper account

IB Gateway routes to IBKR; the paper portfolio now matches the target book.

IB Gateway → IBKR paper account

✔ Paper account rebalanced to the target book

The only money-moving steps — sizing (14) and placement (15) — ran on the laptop.

build_order_plan→Broker.place→ IB Gateway :4002→IBKR paper

What the cloud holds

The model, the data feeds, and the decision (target weights). Output is a signed JSON book. Never sees your account, never sends an order.

What the laptop holds

Your IBKR session, account NAV & positions, and the execution (sizing + orders). Needs only ib_async — no model stack.

Dry-run is the default everywhere · orders require --execute · guards 10–12 each abort before any order · full walkthrough in IBKR_PAPER_TRADING.md
